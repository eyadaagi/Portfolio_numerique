DIGITAL SKILLS · CHAPITRE 2

Prompt Engineering

Apprendre à formuler des demandes précises, tester les résultats et améliorer progressivement ses prompts.

Voir les autres modulesAccueil

Un bon prompt précise le rôle, le contexte, la tâche, le format attendu et les contraintes. Il peut aussi contenir un exemple. Après la première réponse, on peut demander une correction ou une amélioration.

Cas 1 — Comprendre une notion de cours

Prompt initial (faible) : Explique les pointeurs.

Résultat attendu : réponse générale, niveau et exemples non précisés.

Prompt amélioré :

Tu es un enseignant en programmation C. Je suis débutante en première année de licence informatique. Explique les pointeurs avec des mots simples, un petit exemple de code, puis 3 questions pour vérifier ma compréhension. N'utilise pas de notions avancées.

Analyse : le contexte, le niveau, le format et la vérification sont précisés.

Cas 2 — Préparer une révision

Prompt initial : Fais-moi un résumé de Linux.

Résultat attendu : résumé trop large.

Prompt amélioré :

À partir du cours que je vais fournir, crée une fiche de révision sur les commandes Linux étudiées. Classe-les par objectif, donne pour chacune la syntaxe et un exemple simple. N'ajoute pas de commandes qui ne figurent pas dans le cours. Termine par 5 QCM avec correction séparée.

Analyse : la source, les limites et l'organisation de la réponse sont indiquées.

Cas 3 — Corriger un programme

Prompt initial : Corrige mon code Python.

Résultat attendu : l'outil peut réécrire tout le programme sans expliquer les erreurs.

Prompt amélioré :

Voici mon code Python et le message d'erreur. Repère uniquement les erreurs, explique pourquoi elles se produisent, puis propose une correction minimale. Garde mon niveau débutant et ne réécris pas tout le programme sans nécessité.

Analyse : la correction doit rester pédagogique et conserver le travail personnel.

Bibliothèque de 5 prompts réutilisables

  1. Explique cette notion comme à un débutant avec un exemple.
  2. Transforme ce cours en fiche de révision sans ajouter d'informations extérieures.
  3. Pose-moi 10 QCM progressifs et corrige mes erreurs.
  4. Repère les erreurs de mon code et explique-les sans tout réécrire.
  5. Compare ces deux notions dans un tableau avec exemples et différences.
Ces trois cas sont des exemples pédagogiques de prompts. Pour ton rendu final, ajoute tes propres captures d'écran et les résultats réellement obtenus avec les outils que tu as testés.
